# fdの種類とシステムコールの答え

fdの種類ごとに、基本の読み書きと問い合わせのシステムコールを打ち、ZeikOSとLinuxの答えを並べた表である（2026-11-04に測った）。種類ごとの分岐の抜け（ある種類が、別の種類の道へ落ちる形）を探すのが目的で、見つけた差は課題として別に扱う。この文書は測った時点の答えを残すもので、直したら表の行を直す。

## 測りかた

- 同じ試しのプログラム（musl で静的にリンクした Rust）を、WSL の Linux と ZeikOS で走らせた。種類ごとに、表の順でシステムコールを打ち、戻り値か errno を1行ずつ出す。試しのプログラムはリポジトリに置いていない。
- ZeikOS では、`linux-socket-test`のビルドの起動の並びに一時的に足して起こした（測った後に戻した）。
- 種類の作りかたは次のとおりである。
  - 端末: ZeikOS は fd 1 の複製、Linux は pty の子の側（親の側から行を入れておく）。
  - 普通のファイル: `/tmp/seinas`の下に作ったファイルを、`O_RDONLY`と`O_WRONLY | O_CREAT | O_TRUNC`で開く。
  - ディレクトリ: `/tmp/seinas`を`O_RDONLY`で開く。
  - パイプ: `pipe2(0)`。読み端には先に16バイト入れておく。
  - ソケット: listener と、それへ繋いで受け付けた側。受け付けた側には相手から16バイト送っておく。
  - memfd: `memfd_create`の後に4096バイトへ伸ばす。
  - eventfd・timerfd: 待たない印を付けて作る（読みで待たないため）。eventfd の初めの値は1である。
  - 画面と入力: ZeikOS だけ（`/dev/fb0`と、私用の`open_input`）。
- 読みと書きは8バイトで、書くバイトは改行である。`F_SETFL`と`FIONBIO`は、今の値と同じ値を渡す（印を変えない）。`ftruncate`は memfd だけ4096、ほかは0を渡す。

## 読みかた

答えは、成功なら戻り値、失敗なら負の errno（`-9`は`EBADF`、`-11`は`EAGAIN`、`-22`は`EINVAL`、`-25`は`ENOTTY`、`-29`は`ESPIPE`、`-38`は`ENOSYS`、`-107`は`ENOTCONN`）である。最後の欄の分けかたは次のとおりである。

- **同じ**: ZeikOS と Linux の答えが同じ。
- **新しい差**: この表で初めて見つけた差。下の「新しい差」の節にまとめた。
- **1回目の差**: 2026-11-04 の1回目のバグ探しで見つけた差（パイプとソケットの`lseek`が`-ESPIPE`を返さない、パイプの書き端と memfd の`read`が端末の道へ落ちる、memfd の`write`、パイプの`FIONREAD`）。
- **知らない番号**: ZeikOS がその番号を知らず、`-ENOSYS`を返す（`pread64`の17、`pwrite64`の18、`fsync`の74）。番号ごとに下の節にまとめた。
- **ADRに書いた差**: `st_blksize`が0であること（`ADR-0065`の2026-10-20の Addendum に、memfd のほかは0のままと書いてある）。
- **試しの環境による**: 確かめの起動では、ZeikOS の端末に入力が来ないので`-EAGAIN`になる。端末の不具合ではない。
- **比べる相手が無い**: Linux の側（WSL）に同じ装置が無い。

### 新しい差

28の欄は、次の6つにまとまる。

1. **`fcntl(F_GETFL)`が、読み書きの向きと`O_LARGEFILE`を答えない。** ZeikOS は、待たない印を持つ種類（ソケット・eventfd・timerfd・パイプの端）のほかは0を返す。Linux は、書きで開いた普通のファイルに`O_WRONLY`、端末・memfd・epoll に`O_RDWR`を答える。`open`で開いたものと memfd には`O_LARGEFILE`（`0x8000`）も立てる。欄は端末・普通のファイル2つ・ディレクトリ・memfd・epoll の6つである。
2. **端末の`ioctl(TCGETS)`が`-ENOTTY`である。** Linux は0を返し、端末の設定を書く。`tcgetattr`を使うプログラム（行の編集や、端末を生の形に切り替えるもの）が、端末を端末と見ない。musl の`isatty`は`TIOCGWINSZ`で見るので、こちらは通る。
3. **`ftruncate`が、どの種類でも`-EBADF`である（memfd を除く）。** Linux は、書きで開いた普通のファイルを切り詰めて0を返し、ほかの種類（読みで開いたファイル・ディレクトリ・端末・パイプ・ソケット・eventfd・timerfd・epoll）には`-EINVAL`を返す。欄は11である（書きで開いたファイルの1つを含む）。
4. **`ioctl(FIONREAD)`を受けない。** パイプの分は1回目に見つけた。Linux は、端末・普通のファイル・繋がったソケット・memfd でも読めるバイト数を返し、listener と epoll には`-EINVAL`を返す。ZeikOS はどれも`-ENOTTY`である。欄は7つである。
5. **listener の`read`と`readv`が`-ENOTCONN`である。** Linux は`-EINVAL`である（`write`は両方とも`-ENOTCONN`）。欄は2つである。
6. **epoll への`ioctl(TCGETS)`の errno が違う。** ZeikOS は`-ENOTTY`、Linux は`-EINVAL`を返す。欄は1つである（epoll の`FIONREAD`は4.で数えた）。

### 知らない番号

`pread64`（17）、`pwrite64`（18）、`fsync`（74）は、どの種類でも`-ENOSYS`で、終わりの行に「知らない番号」として数えられる（試しのプログラムでは39回）。Linux の答えは次のとおりである。

- `pread64`と`pwrite64`: 普通のファイルと memfd では位置を指定して読み書きする（読みで開いたファイルへの`pwrite64`は`-EBADF`、ディレクトリへの`pread64`は`-EISDIR`）。端末・パイプ・ソケット・eventfd・timerfd・epoll は`-ESPIPE`。
- `fsync`: 普通のファイル・ディレクトリ・memfd は0。端末・パイプ・ソケット・eventfd・timerfd・epoll は`-EINVAL`。
