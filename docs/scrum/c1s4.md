- **Sprint Goal: 達成。** ZeikOSの上で、Seinasのコンポジタ（v0.2.0のreleaseのまま）が起動し、画面全体に背景の色`191e28`を描いた。full checkとCIで毎回確かめる形になった。
- **完了: 23件・69 SP。** 主なものは次のとおり。
  - Seinasのコンポジタの結合（起動して背景の色を描く。プロセスが最初に打った知らない番号を名指しする）
  - 壁の時計（`CLOCK_REALTIME`。起動時にRTCを1回読む。`ADR-0090`）
  - ext2の2段目の間接ブロックの読み
  - epoll・eventfd・timerfd（`ADR-0088`）
  - ソケットの待たない印（`O_NONBLOCK`）
  - memfdのフラグ・封・`FD_CLOEXEC`
  - プロセスの終わりの印で、どの待ちも起こす
  - getrandomのflagsの確かめ
  - `F_DUPFD`のコピーが端を数える
  - fdの上限を32にする（`ADR-0091`）
  - 待った後に書き先を確かめ直す（読みと`poll`）
  - Ring 3のタスクのスタックの余裕（`spawn`の道でfdの表をコピーしない）
  - `readv`・`writev`のiovecのコピーを流れごとに持つ
  - 閉じたlistenerに残った接続を、後から作ったlistenerが受け付けない
  - スレッドのイメージの待ちを、ティックの位置で変わらない形にする
  - QEMUとSeinasの重い作業をホストのロックで分ける（`ADR-0089`）
  - バグ探し（ZeikOSとSeinasの両方）
  - Seinasの、IMEのソケットを開かない引数（`--no-ime-socket`）
  - Seinasの、ZeikOS向けのreleaseと起動の手順（実際に出たのはコンポジタだけのv0.2.0。タスクバーを含むreleaseはC2S1で出す）
  - Seinasのタスクバーが、コンポジタのソケットができるまで待ってつなぎ直す
  - Seinasの側の、ZeikOSへの要求の文書を今のZeikOSに合わせて書き直し、要求を順番つきで渡す
  - SeinasのIMEの後片付けの続き（grabだけを外したときに残る押されたキー、古いgrabの扱い）

## Sprint Retrospective

### 続けたいこと

- 落ちたら、直す前に止まって報告する。判定の範囲を緩めない。
- 確かめは経過時間ではなく数で行い、sabotageで落ちることも確かめる。
- コンパイラに数え上げさせる（`Copy`を外す）ような、漏れの無い洗い出し。
- pushの例外の4つの条件を守った運用。

### 困ったこと

- スレッドを入れた後（M3a）も、「プロセスは1本の流れ」という前提が残っていた（待った後に書く形、`readv`・`writev`のiovecのコピー、待つ間に握る添字）。
- fdの表が満杯のときの順序の誤りが、同じ形でまとめて出た（`accept`・`open`・画面のfd・`recvmsg`の`SCM_RIGHTS`）。
- デバッグビルドでfdの表のコピーがスタックに載り、スタックの余裕を隠していた（Ring 3のタスクのスタック、fdの上限）。
- レビュー側（Claude）の誤り。スプリントの開始の確認漏れ、`dup`・`dup2`・`dup3`と`ci-wait.sh`の誤認、IT用語の言い換え、古い報告と新しい報告の取り違えがあった。
- SeinasのCCがJiraへ自分で起票し、`pkill`を使った（本人が報告済み）。
- 指示の伝達を待って、CCが止まる時間があった。

### 次に試すこと

- C2S1の最初に、「スレッドの前提」と「fdの表が満杯のときの順序」の2つで、横断の棚卸しを1回行う（読むだけ）。
- CCの報告の1行目に、日時とHEADを書く。
- レビュー側は、スプリントの開始の日にボードの状態を確かめる。
