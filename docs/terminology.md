# 用語と書き方

ZeikOSのコミットメッセージ、ドキュメント、ADR、コードコメント、検査の出力、報告での、用語の選び方である。決まりの本体は`CLAUDE.md`の「コミットメッセージ」にある。ここには語の一覧を置く。

## 決まり

- IT用語は、一般に使われている形（カタカナ語か英語）で書く。和語に言い換えない（運用者の決定。2026-10-08。2026-10-16に、語を下の3つに分けた）。
- 新しい言葉を作る前に、一般のIT用語が在るか確かめる。迷ったら、Linux・x86_64（Intel SDM）・Rustのドキュメントでの呼び方に合わせる。
- コードの名前（関数・型・featureの名前）が英語の用語なら、文章でもその言い方に合わせる（例: `excursion stack`、`quarantine`）。
- 普通に使われる日本語のIT用語と、この開発の決まった呼び名は、そのまま使う（下の「残す語」）。
- 既存の文章は、「使わない語」から順に、別の課題でまとめて言い換える。それまでは古い言い方が残るので、下の表で読み替える。
- 名前で参照されている見出しを言い換えるときは、参照している側を同じコミットで直す（`CLAUDE.md`の「エージェント向け設定ファイルの扱い」）。
- 課題キーの位置や、コミットメッセージの行数など、ほかの決まりは変わらない。

## 残す語

普通に使われる日本語のIT用語と、この開発の決まった呼び名である。そのまま使う。

| 語 | 意味 |
| --- | --- |
| 判定 | verdict。検査の結果の行 |
| 破壊テスト | sabotage test。この開発の呼び名 |
| 入口 | システムコール・割り込みのエントリ |
| 起動ログ | ブートログ |
| 作業ツリー | git worktree |
| 全検査、基本の検査 | `cargo xtask full`と`cargo xtask check` |
| 試験 | テスト（ホストの試験・停止性の試験） |
| 装置 | デバイス |
| 版 | バージョン |
| 隔離 | quarantine。コードの名前は`quarantine` |

上の3つの表に無い語は、一般に使われている形のIT用語なら、そのまま使う。和語に言い換えたくなったら、まず「使わない語」の表に当たらないかを見る。
