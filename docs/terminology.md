# 用語と書き方

ZeikOSのコミットメッセージ、ドキュメント、ADR、コードコメント、検査の出力、報告での、用語の選び方である。決まりの本体は`CLAUDE.md`の「コミットメッセージ」にある。ここには語の一覧を置く。

## 決まり

- IT用語は、一般に使われている形（カタカナ語か英語）で書く。和語に言い換えない（運用者の決定。2026-10-08。2026-10-16に、語を下の2つに分けた）。
- 新しい言葉を作る前に、一般のIT用語が在るか確かめる。迷ったら、Linux・x86_64（Intel SDM）・Rustのドキュメントでの呼び方に合わせる。
- コードの名前（関数・型・featureの名前）が英語の用語なら、文章でもその言い方に合わせる（例: `excursion stack`、`quarantine`）。
- 普通に使われる日本語のIT用語と、この開発の決まった呼び名は、そのまま使う（下の「残す語」）。
- 既存の文章の言い換えは、語のまとまりごとに、言い換えだけのコミットで行う（2026-10-16の運用者の決定。言い換えたコミットは`.git-blame-ignore-revs`に載せる）。
- 名前で参照されている見出しを言い換えるときは、参照している側を同じコミットで直す（`CLAUDE.md`の「エージェント向け設定ファイルの扱い」）。
- 課題キーの位置や、コミットメッセージの行数など、ほかの決まりは変わらない。

## 使わない語

左の語は使わない。「使う語」を使う（運用者の決定。2026-10-16）。

この表は、基本の検査（`cargo xtask check`）が読む。追跡しているファイルに「当たる形」が新しく入ると、検査が止める。列の読み方は次のとおりである。

- 当たる形: 検査が探す文字列。インラインコードで書き、複数ならコードを並べる。空なら、その行は検査しない（別の行の当たる形に含まれる）。
- 除く形: 当たる形を含むが、一般の意味である語。この中に収まる当たりは数えない。
- 当たる形の直後に「→」が続く所は、言い換えの例なので数えない（`CLAUDE.md`の例がこれである）。この文書そのものも読まない。

## 残す語

普通に使われる日本語のIT用語と、この開発の決まった呼び名である。そのまま使う（運用者の決定。2026-10-16）。

| 語 | 意味 |
| --- | --- |
| 判定 | verdict。検査の結果の行 |
| 破壊テスト | sabotage test。この開発の呼び名 |
| 入口 | システムコール・割り込みのエントリ |
| 起動ログ | ブートログ |
| 作業ツリー | git worktree（「木」だけの言い方は使わない） |
| 全検査、基本の検査 | `cargo xtask full`と`cargo xtask check` |
| 試験 | テスト（ホストの試験・停止性の試験） |
| 装置 | デバイス |
| 版 | バージョン |
| 隔離 | quarantine。コードの名前は`quarantine` |
| 起こす | プログラムをspawnする、QEMU・AP・VMを起動する、待っているタスクをwakeする。文脈で読める |
| 印、目印 | 状態を示すビット・行 |
| 段（段階の意味） | 開発の段階、実装の段。ページテーブルの「N段目」だけはレベル（上の表） |
| 回す（検査を） | 実行する |
| 見張る、見張り（全検査の） | `cargo xtask full --watch`と対になる言い方 |
| 遠征（スタック） | excursion stackの訳。コードの名前はexcursion |
| 畳む、畳まれる | 例外でプロセスを終わらせる。コードの名前はfold |
| 打鍵 | キーの押しと離し |
| 世代が退く | quarantineのgenerationがretireする |
| 参照、取り直し | 起動ログなどの、比べる元の記録（`xtask/reference/`）と、その作り直し |
| 緑、赤 | 検査の通過と失敗 |
| 並行実行 | 以前の「並走」 |

上の2つの表に無い語は、一般に使われている形のIT用語なら、そのまま使う。和語に言い換えたくなったら、まず「使わない語」の表に当たらないかを見る。
