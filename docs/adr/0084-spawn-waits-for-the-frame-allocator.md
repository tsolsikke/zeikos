# 0084. `spawn`と切り離したスロットの読み込みも、フレームのアロケータを待ってから借りる

## Status

Accepted（2026-10-12に運用者が案A〔待つ形に揃える〕を決めた）。

## Date

2026-10-12

## Context

フレームのアロケータは大域に1つで、貸し出しで排他している（`kernel/src/frame_allocator.rs`の`take`と`Loan`）。借りられないのは、メモリが足りないからではない。ほかのタスクが借りている間だけである。

2026-10-08に、システムコール（`mmap`・`munmap`・`mprotect`・`brk`・`ftruncate`）は、借りられないとき1ティックずつ眠って待つ形にした（`kernel/src/syscall.rs`の`borrow_allocator`。上限100ティック）。決まりは「借りる前に、プロセスの状態を読まない」である。借りられずに眠るとBKLを手放すので、眠る前に読んだ値は起きたときには古いかもしれない。

一方、`spawn`と、切り離したスロット（`|`の左）の読み込みは、借りられないと待たずに`AllocatorUnavailable`（`-EAGAIN`）で断っていた。さらに`spawn`は、空きフレームの数を数えるために借りてすぐ返し、読み込み（`load_user_program_from`）でもう1度借りていた。その間に別のタスクが入ると、2度目で借りられない。

読み込みは、イメージを写す間アロケータを持つ（最長約23 ms）。シェルの`|`では、左の読み込みと右の`spawn`が重なりうる。これまでは、切り離して起動する入口が左のRing 3への入場を待つことで重ならないようにしていた（`ADR-0063`の(b3)）。M3aでスレッドが入ると、重なる機会が増える。

Linuxでは、この形で`fork`は失敗しない。`kernel/fork.c`の`copy_process`は、確保に失敗すると待ち直さずに`-ENOMEM`を返す（`-EAGAIN`はプロセス数とスレッド数の上限のとき）。ただし、確保の側（`GFP_KERNEL`）は回収して待ち、小さな確保は「暗黙に失敗しない」（`include/linux/gfp_types.h`）。ZeikOSの貸し出しは、Linuxでいえばゾーンのロックで短く待つ所に当たる。

## Decision

1. **`spawn`の入口（`spawn_from_ring3`と`spawn_with_piped_stdin_from_ring3`）は、引数だけの確かめ（パスと`argv`と`envp`のコピー、プログラムを探すこと）の直後に、`borrow_allocator`と同じ形で待って借りる**（`borrow_allocator_for_spawn`。1ティックずつ眠る。上限100ティック）。**stdinの予約を見ること・消費すること（`peek_pending_stdin`・`take_pending_stdin`・`claim_reserved_reader`）と、記録の控え（`save_records`）は、借りた後に行う。** 以前はパイプの右の入口が予約を最初に見ていたので、借りた後へ移した（予約が無いときの`-EINVAL`は、引数の誤りや`-ENOENT`より後に返るようになった）。
2. **借りた貸し出しを、`spawn`（`spawn_with_loan`）から読み込み（`load_user_program_with`）へ、そのまま渡す。** 空きフレームの数（会計の`free_before`）も、その貸し出しのまま数える。「借りてすぐ返し、後でもう1度借りる」形はやめた。読み込みの前に断る出口では、貸し出しが落ちるときに返る。
3. **切り離したスロットの読み込みのタスク（`run_detached_request`）は、自分のスロットの引数を読む前に、譲りながら待って借りる**（`borrow_allocator_by_yielding`。上限100ティック）。このタスクはカーネルのタスクでBKLを持たないので、眠るのではなく譲る。
4. **上限まで待っても借りられなければ、今と同じ`-EAGAIN`を返す**（切り離したスロットは、起動できなかった子として`wait_child`が`-EIO`を返す。これも今と同じ）。stdinの予約は消費せずに残り、使われなかった予約はシェルの`wait_child`が消す。記録はまだ控えていない。
5. **読み込みの経路で、アロケータを借り直してはいけない。** 受け取った1本だけを使う。借り直すと、自分の持つ貸し出しを自分で待ち、1秒後に失敗する。今のイメージはメモリの上に在り（`kernel/src/vfs.rs`の`root_image`）、`common/src/ext2.rs`の`FileImage`はスライスを写すだけである。virtio-blkがアロケータを受け取るのは起動のときの`setup`だけである（2026-10-12に、借りる所を全部当たって確かめた）。**将来、ディスクから直に読む形（ページキャッシュ）にするなら、読み込みが借りたものを渡すか、別の置き場から取る。**
6. **順番は保証しない。** 待つ側が何人いても、空いた瞬間に`take`した者が借りる。負け続けた側は、1秒で`-EAGAIN`になる。
7. 起動の直線と起動時の確かめ（`kernel/src/main.rs`）から呼ぶ`spawn`と`load_user_program_from`は、今までどおり待たずに借りる（ほかに借りる者が居ない）。

### 検査

- **`pipe-test`の確かめを2つ足した**（`PIPE_TEST_CHECKS`）。`--pipe-test --with <名前>`で実行する。
  - `spawn-detached-returns-early`——左の読み込みが貸し出しを2ティック持つ間に、右が`spawn`する。**右は待ってから起動する**（spawnの入口が待った刻みが1以上で、諦めた回数が0。起こせなかった右は`/bin/nonexist`だけ）。2026-10-12までは破壊テストだった（右が`cannot run`になることで、入場を待つことを確かめていた）。待つ形になって、落ちる判定が無くなったので、確かめへ移した。
  - `allocator-held-past-the-wait-limit-test`——最初の`|`の左だけが200ティック持つ。**最初の右（`/bin/cat`）だけが上限まで待って`-EAGAIN`になり、予約は残らない**（消した予約が`nonexist`の分と合わせて2で、後の`|`は通る）。
  - どちらの確かめも、中身のバイト一致は求めない。入場を待たずに戻るので左と右が同時に走り、左のカーネルの行が右の出力の行の途中に割り込む（実測）。中身の判定は、既定の`pipe-test`が持つ。
- **破壊テスト`spawn-refuses-without-waiting-test`**（直す前の形。待たずに1度だけ試す）を、`pipe-test`の破壊テストに入れた。`spawn-detached-returns-early`の重なりの上で、右が`-EAGAIN`で起動できず、判定8（起こせなかった右は`/bin/nonexist`だけ）で落ちる。
- 計測の行（`pipe:`）に、spawnの入口が待った刻みと諦めた回数を足した。

## Alternatives Considered

- **今のまま断る**（案B）——採らない。シェルのパイプなど、重なる場面で偶然に`-EAGAIN`が返る。M3aでスレッドが増えると、重なる機会が増える。Linuxと違う振る舞いになる。
- **待つ位置を`spawn`の中（読み込みの直前）に置く**——採らない。`spawn`はBKLを解いた後に呼ばれ、その前に予約と記録を触っている。眠る前にプロセスの状態を読まない決まりを守れない。
- **借りた貸し出しを一度返し、読み込みでもう1度待って借りる**——採らない。間に別のタスクが入り、待ちが2回になる。会計の`free_before`と読み込みの間に、別のタスクがフレームを取る隙も開く。
- **諦めたときの`errno`を`-ENOMEM`にする**——採らない。Linuxの`fork`の`-ENOMEM`は確保が失敗したときで、ここは「今は借りられない」である。シェルとほかの利用者が今見ている`-EAGAIN`のままにする。

## Consequences

- 重なっても、右の`spawn`は待ってから起動する（実測で8〜13ティック待った）。
- `spawn`は最長1秒待つ。そのとき、待つ側の利用者には応答が遅れて見える。
- 切り離して起動する入口が左の入場を待つこと（`ADR-0063`の(b3)）は残した。待たなくても壊れなくなったが、左のカーネルの行が右の出力に割り込むのを避けている。
- 読み込みの経路でアロケータを借り直さない決まりが増えた。ページキャッシュを入れる段で、この決まりを見ること。
