# 0086. セルフホスティング（ZeikOSの上でZeikOSとSeinasを編集・ビルド・切り替えて動かす）を長期のゴールの1つにする

## Status

Accepted（運用者の決定。2026-10-15。記録の正本はConfluenceの「長期ゴール — セルフホスティング（ZeikOS・Seinas）」のページで、このADRはその写しと、コードと文書から読んだ現在地である）

## Date

2026-10-15

## Context

ZeikOSは学習目的のホビーOSで、「細く長く」「一つ一つを理解しながら確実に積み上げる」を方針にしている（`CLAUDE.md`の「プロジェクト概要」）。2026-10-04に、Linuxカーネルとシステムコールで完全互換にし、Linux向けに静的にリンクしたプログラムをそのまま動かすことを目指すと決めた（`ADR-0074`）。その最初の相手がWaylandコンポジタのSeinasで、2026-10-14までにスレッド（`clone`・futex・スレッドの終わり方）が入った（`ADR-0085`）。

「Linuxのプログラムがそのまま動く」の先に、長期の目標を1つ置く。ZeikOSの上でZeikOSとSeinas自身のソースを編集し、ビルドし、できたものに切り替えて動かす——セルフホスティングである。これは「どこまでLinux互換か」を測る物差しにもなる。エディタ、ビルドの道具（C とRust）、大きなファイルを扱うファイルシステム、十分なメモリ、プロセス生成と動的リンクが、順にそろわなければ届かない。

今のスプリントの優先順位は変えない。Sprint Goal（M3a。スレッドを使うmuslのRustのプログラムが動く）と、その次（M3b。シグナル）はそのままである。

## Decision

ZeikOSの上で、ZeikOSとSeinasのソースを編集し、ビルドし、できたものに切り替えて動かせることを、長期のゴールの1つにする。

### 段階

| 段 | 内容 | 位置づけ |
|---|---|---|
| S0 | 中でソースを読み書きする | 準備 |
| S1 | Linux向けの静的な道具（busybox、git）が動く | 準備 |
| S2 | 中でCをコンパイルする（tccなど） | 準備 |
| S3 | 中でrustcとcargoが動く | 準備 |
| S4 | 中でZeikOSとSeinasをビルドできる | **ゴールの達成とする** |
| S5 | 中でビルドしたものに切り替えて動かす。中で全検査も回す | 発展の目標 |

### 決まったこと

- libcはmuslとglibcの両方に対応する。時期は後で決める。
- SeinasはSmithayを使うので、proc-macroと`build.rs`への依存は避けない。依存は調べて記録する（`docs/wayland-inventory.md`の形）。
- JiraのEpicは作らない（粒度が大きすぎるため）。段階ごとの課題は、具体的な作業になった時点で起票する。

### これからの設計で守る条件

各段の設計のときに、次を確かめる。

- プロセス生成を、Linuxの`clone`・`execve`・`wait4`の形にそろえていく。ZeikOS固有の`SYS_SPAWN`の族（`kernel/src/abi/private.rs`）を増やす向きには進まない。
- 動的リンク（`PT_INTERP`、共有ライブラリの`mmap`、`dlopen`）を、いずれ入れる（`ADR-0074`の「決めないこと」で保留していたもの）。
- シグナル（M3b。`ADR-0081`）と、Linuxに合わせたプロセスの終わり方（`ADR-0085`の決定3で持ち越した、主スレッドの`exit`がほかのスレッドを待つ形を含む。スレッドの終わり方の課題（M3a）の完了で持ち越しにした3点——主スレッドがパイプ・キーボード・タイマで眠っている間は起こさない、主スレッドの`exit`は待たない、主スレッドの`set_tid_address`の番地を終わりに0にしない——は`docs/deferred-decisions.md`の行にある）。
- `/proc`の一部（`/proc/self/exe`など）。
- 数千のファイルと大きなファイルを扱えるファイルシステムと、保存の仕組み。
- GB単位のメモリ。
- 性能は後にする。BKL（`ADR-0023`）のままでも動くことを先に目指す。

## 状況の確かめ（2026-10-15。zeikosのコードと文書を読んだ範囲）

- **S0（中でソースを読み書きする）。** 一部できている。vi風のエディタ`zi`がターミナルの上で動き（`docs/roadmap.md`の「zi」）、ext2の書き込み（追記・作成・切り詰め・ディレクトリの作成。起動ログの`fs-write`・`fs-create`・`fs-mkdir`の行）と、像のvirtioディスクへの書き戻し（`fs-image-flush`）が在る。届いていないのは大きさである——像は32 MiB（`kernel/build.rs`）で、ext2の二重間接ブロックは未対応（4 MiBを超えるファイルは作れない。`kernel/src/main.rs`の`ext2-corrupt`の節のdoc）。ZeikOSの追跡下のソースは402ファイル・17 MiB（`git ls-files`。2026-10-15）で、最大のファイルは1.8 MiB（`xtask/src/main.rs`）なので、ソースだけなら像に入るが、`target/`（ビルドの成果物。メインの木で33 GiB）は桁が違う。パスの上限は256バイト、同時に開けるファイルは16（`PATH_MAX`・`MAX_OPEN_FILES`）。
- **S1（busybox・gitが動く）。** 動かない。musl で静的にリンクしたRustとCのプログラムは走る（起動のたびに11本。`m1-rust`・`m1-c`・`m3a-*`。`ADR-0074`・`ADR-0085`）が、プロセス生成はZeikOS固有の`spawn`（親が待つ形。`ADR-0063`）だけで、`fork`・`execve`・`wait4`は無い。シグナルは登録するだけで配送しない（`ADR-0081`）。同時に走るプロセスは2スロット・深さ2、スレッドは1プロセスに4本（`USER_TASK_SLOTS`・`MAX_EXCURSION_DEPTH`・`THREAD_TASKS`）。busyboxもgitも`fork`と`execve`とシグナルを前提にするので、S1はプロセス生成とシグナルの後である（推測——どちらも動かして確かめてはいない）。
- **S2（中でCをコンパイルする）。** 未着手。tccのような1バイナリのコンパイラなら、静的リンクの像として読み込める見込みはあるが、出力を書く大きなファイル、`execve`で実行する道、ヘッダとライブラリをディスクに置く場所のどれも無い（推測——tccの要求は調べていない）。

## Alternatives Considered

- **Epicを作って段階を課題に割る。** 粒度が大きすぎ、段階の中身が今の知識では決められないので作らない。段階ごとの課題は、具体的な作業になった時点で起票する。
- **libcをmuslに絞る。** Seinasと今の像はmuslで足りるが、glibcでしかビルドされない道具（S1・S3で出る見込み）を避けられない。両方に対応し、時期は後で決める。
- **proc-macroと`build.rs`に依存しないようにSeinasを作り替える。** SmithayがSeinasの土台なので避けない。依存を調べて記録する。
- **S5をゴールにする。** 「中でビルドできる」（S4）で達成とし、切り替えと中での全検査は発展の目標にする。全検査は1回60分でQEMUを多数起こすので、中で回すには性能の段が要る。

## Consequences

- 得るもの——Linux互換の進み具合を測る物差しと、各段の設計で確かめる条件の一覧。プロセス生成・動的リンク・シグナル・ファイルシステム・メモリの各課題が、この目標に向く。
- 失うもの——無い。今のスプリントの優先順位は変えない。性能（BKLの分割）はこの目標でも後である。
- 守る条件は各段の設計のときに確かめる。守れないと分かったときは、このADRにAddendumで理由と代わりの道を書く。
- 関係するADRから、このADRを参照する（`ADR-0001`・`ADR-0023`・`ADR-0063`・`ADR-0074`・`ADR-0081`・`ADR-0085`）。
