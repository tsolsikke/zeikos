# 0077. ディスクの像の大きさに比例する費用を外す

## Status

Accepted（2026-10-05に運用者が設計を承認し、同じ日に実装した）。

## Date

2026-10-05

## Context

- Linux向けの実行ファイル（数MiB）を置くために、ディスクの像を2MiBから32MiBへ上げた。全検査が、479項目のうち10項目の時間切れで落ちた。起動が、1回あたり約9秒延びていた。
- 区間ごとに測って、原因を分けた（`docs/verification-coverage.md`の「ディスクの像の読み書きの所要」）。延びていたのは5つの区間で、どれも像の大きさ（か、使っている量）に比例していた。
  - ブートローダが、ESPの像を読んでRAMに置く（32MiBで約3.6秒）。装置（virtio-blk）が在る回は、カーネルはその像を使わない。
  - 起動時に、装置から像を読む（約0.6秒）と、装置へ書き戻す（約2.8秒）。4KiBずつの要求で、32MiBなら8,192回になる。費用は、バイト数ではなく要求の回数に付いていた。
  - 像の全体の検査値を計算する（約2.5秒）。
  - 壊した像の検査が、使っている量の全体を、壊し方ごとに写し直す（約0.3秒）。
- 像の全体を読む・書く形は、`ADR-0034`の決定である。ext2の実装が、像の全体のバイト列を借りる形で書かれている。同じADRが、見直すきっかけを「像がRAMに載らない大きさになったとき、または部分読みが実測で要る場面が出たとき」としていた。
- 像の全体をRAMに置くことをやめる（ブロックのキャッシュと、変わったブロックだけを書く形）のは、ext2の読む側と書く側の作り直しになる。ここでは扱わない。

## Decision

像の全体をRAMに置く形（`ADR-0034`）は、そのままにする。その上で、像の大きさに比例していた費用を、1つずつ外す。

### 1. 区間ごとの所要を、起動ログに出す

ブートローダが1行、カーネルが2行、`fs-timing:`の行にサイクル数を出す。値は実行ごとに揺れるので、判定には載せない。直しの前後と、像の大きさを変えたときを、同じ行で比べるための行である。

### 2. 起動時の読み書きは、1MiBまでの要求にまとめる

- 1回の要求の上限は、装置が申告する区画の上限（`VIRTIO_BLK_F_SIZE_MAX`の`size_max`）と、こちらで決めた上限（1MiB）の、小さいほうにする。データは1つの区画（物理的に連続した範囲）で渡すので、要求の上限は区画の上限である。
- **装置が上限を申告していなければ、装置の側の上限は無いものとして扱う。** virtioの仕様では、この機能を申告しない装置は、区画の大きさを制限しない。こちらの上限だけが効く。QEMUのvirtio-blkは、`size_max`を申告しない（`seg_max`だけを申告する。実測で254）。
- 受けると答えていない機能でも、申告された上限には従う。`seg_max`が申告されていて0なら、装置を使わずに止まる。
- こちらの上限を1MiBにしたのは、起動時の要求を、割り込みを禁じたままポーリングで待つためである。1回の待ちは約1ミリ秒だった（実測）。
- 実行時の保存は、像の全体を1回の要求で出す形のままである。装置が上限を申告していて、像の全体がそれを越えるときは、要求を出さずに保存の失敗として返す。

### 3. 装置から起動する回は、ESPに像を置かない

- 検査の道具が、virtio-blkを付けてディレクトリから起動する回には、ESPへ像を置かない。ブートローダは「像が無い。カーネルは装置を使う」と1行出して進む（この道は、以前から在る）。
- 起動媒体のイメージ（VirtualBoxと実機に渡すもの）と、virtio-blkを付けない変種には、今までどおり置く。「起動媒体1つで、装置の在る・無しのどちらでも起動する」（`ADR-0068`）は、起動媒体の側で保つ。
- ブートローダは変えていない。

### 4. 検査値は、管理用の部分だけを覆う。像の全体の検査値は、ボリュームの名前の欄に書く

- 起動時にカーネルが計算する検査値の範囲を、像の全体から、**管理用の部分**へ絞る。先頭から、グループ0のinodeの表の終わりまでである（スーパーブロック、グループの記述子、ビットマップ、inodeの表）。大きさは、像の大きさやファイルの中身の量に依らず、inodeの数で決まる。
- ホストの検査は、同じ範囲を、像のファイルから計算して突き合わせる。範囲の決め方は`common`のext2に1つだけ置き、カーネルとホストの両方が使う。
- **管理用の部分だけでは、ファイルの中身だけが違う古い像を見分けられない**（大きさが同じなら、管理用の部分は変わらない。時刻は、ビルドのときに潰してある）。そこで、**ビルドのときに、像の全体の検査値を、スーパーブロックのボリュームの名前の欄（`s_volume_name`）へ文字で書く**（`zeikos-`に16進8桁を続けた15文字）。この欄は管理用の部分に入るので、中身が1バイトでも違う像は、管理用の部分の検査値も違う値になる。
- RAMの像から起動した回は、今までどおり、ビルドしたときの値と比べる。比べる値が、管理用の部分の検査値になった。
- **像の全体のバイト一致は、像を取り出す検査が持つ**（RAMの複製をQEMUから取り出して、ビルドした像のファイルと比べる。以前から在る）。既定の起動は、像の全体を歩かない。

**ボリュームの名前の欄を選んだ理由。** この欄は、`e2label`や`dumpe2fs`や`blkid`で見える。人が像を手に取ったときに、どのビルドの像かが道具で読める。使える欄を4つ比べた。

| 欄 | 見え方 | 採らなかった理由 |
|---|---|---|
| ボリュームの名前（`s_volume_name`。16バイト） | `e2label`・`dumpe2fs`・`blkid`で見える | **採った。** 道具が勝手に書き換えない。人が名前を付ける欄なので、付いていても道具は驚かない |
| UUID（`s_uuid`。16バイト） | `dumpe2fs`・`blkid`で見える | 像の身元として道具が使う欄である。ビルドを決定的にするために、固定の値を入れてある。中身ごとに変えると、その固定が無くなる。16進の並びで、人には読みにくい |
| 最後にマウントした場所（`s_last_mounted`。64バイト） | `dumpe2fs`で見える | Linuxが、マウントのたびに書き換える。像をホストでマウントすると、印が消える |
| スーパーブロックの末尾の予約の領域 | 道具では見えない | e2fsprogsが、後の版で意味を与えうる（ext4は、予約の領域を少しずつ使ってきた）。見えない値は、食い違ったときに気づきにくい |

**ボリュームの名前を、像の目印として使っている。** 人がこの像に別の名前を付けると（`e2label`で書き換えると）、RAMの像から起動したカーネルは、古い像と同じ扱いで止まる。

### 5. 壊した像の検査は、写すのを1回にする

最初に1回だけ、使っている量を作業領域へ写す。壊し方ごとに、書き換える数バイトの元の値を控え、検査の後で元へ戻す。**戻した後、健全な対照（解析と、5つの読み出し）がもう1度通ることを、壊し方ごとに確かめる。** 「前の壊し方が残らない」を、写し直しではなく、戻すことと確かめで保つ。

### 6. ホストの側の像は、穴の在るファイルとして写す

検査の道具が像を写すとき（回ごとの置き場の装置の像と、ESPの像）、0だけのブロックを書かずに飛ばす。ファイルの長さは変えない。写した後の長さが元と同じであることを、検査が確かめる。

## Alternatives Considered

- **ブロックのキャッシュへ移る**（要るブロックだけを読み、変わったブロックだけを書く）: 今は採らない。ext2の公開の関数のうち像を受け取るものが27、カーネルの側で像の全体を借りている所が19在り、作り直しになる。読むシステムコールの中で装置を待つ場面もできる。延びた時間の正体は、上の5つで、どれもキャッシュを待たずに外せた。RAM（像の大きさだけ要る）と、実機の遅い媒体での保存のために、別の段で扱う。
- **検査値を、全体のまま速くする**（語の単位で計算する）: 採らない。式が変わるので、ホストの側と装置の読みの試験の式も変えることになる。速くなっても、像の大きさに比例したままである。
- **検査値を、試験の構成でだけ計算する**: 採らない。既定の起動が「装置から読んだものが、ホストのファイルと同じ」と主張しなくなる。RAMの像の取り違えも、既定の起動で見つからなくなる。
- **装置の有無を、ブートローダが調べて、読むかどうかを決める**: 採らない。ブートローダがPCIを調べることになる（「ローダは薄く」。`ADR-0008`）。像を置くかどうかは、起動のさせ方を知っている側（検査の道具と、起動媒体を作る側）が決められる。
- **壊した像の検査を、管理用の部分だけに絞る**: 採らない。切り出した像が、それ自体で読み切れる形でなくなる（検査は、ルートのディレクトリやファイルのブロックも読む）。写すのを1回にするほうが、効果が大きく、差分が小さい。
- **起動時の要求を、像の全体で1回にする**: 採らない。割り込みを禁じたまま待つ時間が、像の大きさに比例して延びる。

## 決めないこと

- ブロックのキャッシュと、変わったブロックだけを書く形（次の段）。
- RAMの像から起動する回で、ブートローダが像を読む時間（QEMUでは1MiBあたり約0.11秒）。渡された像を別のフレームへ写さずに、そのまま使う形も、ここでは扱わない。
- 区画の上限を申告する装置での、実行時の保存（要求を分けて出す形）。

## Consequences

- 起動の時間のうち、像の大きさに比例する分が、ほぼ無くなった。残るのは、装置の読み書きの、1MiBあたり約2ミリ秒である。実測は`docs/verification-coverage.md`の「ディスクの像の読み書きの所要」に在る。
- 既定の起動が確かめる範囲は、狭くなった。像の全体を歩いて検査値を出すことを、やめた。ファイルのブロックが装置から正しく読めたことは、像を取り出す検査と、起動時にファイルを読んで中身を比べる確かめが見る。
- 既定の起動のESPは、起動媒体のESPと、像の有無が違う形になった。起動媒体の形は、`media-only`と`pc-no-virtio`の変種と、VirtualBoxの判定が見る。
- 像のボリュームの名前に、意味ができた。
- 像の全体をRAMに置く形は残っている。RAMは、像の大きさだけ要る（RAMの像から起動する回は、その2倍）。QEMUのRAMは256MiBなので、像を大きくし続けることはできない。
