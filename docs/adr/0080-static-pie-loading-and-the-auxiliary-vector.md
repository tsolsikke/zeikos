# 0080. 静的な位置独立の像をずらして載せ、補助ベクタを積む

## Status

Accepted（2026-10-05に運用者が刻みの計画を承認し、10-05から10-06にかけて実装した）。

## Date

2026-10-06

## Context

- 目指す先は、Linux向けにmuslで静的リンクしたプログラム（Seinas）を、そのまま動かすことである（`ADR-0074`）。muslの静的なプログラムは、既定で位置独立の像（`ET_DYN`。静的PIE）としてリンクされる。
- このカーネルのローダーは、位置を決めてリンクした像（`ET_EXEC`）だけを受け付けていた。実行ファイルは32KiBまでで、像の全体を静的な配列へ写してから載せていた。スタックの上端・ヒープの上限・`mmap`の始まりは、ばらばらの定数だった。
- 初期スタックには`argc`・`argv`・`envp`と、補助ベクタの終端（`AT_NULL`）だけを積んでいた。muslの`_start`と`__libc_start_main`は、補助ベクタから`AT_PHDR`・`AT_PHNUM`・`AT_RANDOM`などを読む。静的PIEは、`AT_PHDR`から自分の載った位置を求めて、自分で再配置する。
- このカーネルは、まだ乱数の仕組み（エントロピーをためて混ぜる所）を持たない。

## Decision

### 1. 載せる側は、像の全体を持たず、範囲を読む口から要る所だけを読む

- 範囲を読む口（`common::image_source::ImageSource`。`len`と`read_at`）を置き、メモリのバイト列（起動時に埋め込んだプログラム）とext2の上のファイル（`spawn`）の2つの実装を持つ。
- 載せる関数は、フレームを1枚借りて像の先頭（4KiBまで）を読み、ヘッダを検査する。区画の中身は、写す先のフレームへ、像から直に読む。
- 静的な配列（32KiB × 深さ2 × スロット2）は無くした。ファイルの上限は16MiBである（ext2が読めるのは、2段目の間接ブロックを使わない約4.05MiBまでで、越えるファイルは名前のある失敗で断る。2段目の間接ブロックは別の課題である）。

### 2. 配置は、像の種類ごとに1つ持つ

- `ET_EXEC`（今までの形）: 像はリンクした番地（`0x400000`から）。スタックは`0x800000`の下の4ページ（`ADR-0041`のAddendum）。ヒープの上限は、スタックの見張りのページの下端。`mmap`は`0x1000_0000`から。
- `ET_DYN`（静的PIE）: 像の全体を`0x400000`だけずらす（**決まった量である。** 番地を毎回変えること——ASLR——は、していない）。像は端から端まで32MiBまで。ヒープは像の末尾から`0x0fff_f000`まで。`mmap`は`0x1000_0000`から、スタックの見張りの手前まで。スタックは`0x7f_ffff_f000`の下の256KiBを起動のときに全部写し、その下の1ページは写さない。
- どちらの配置も、スタックの下に写さないページを1枚置く。ヒープと`mmap`は、その番地を越えて配らない。
- 載せる位置は、ヘッダを読んだ時点で計画として決める（`ElfHeaders::plan`）。`PT_INTERP`を持つ像（動的リンクを求める）、実行できるスタックを求める像（下の4）、置いてよい範囲に収まらない像は、1枚も写す前に断る（`-ENOEXEC`）。

### 3. 補助ベクタ（auxv）を、全部のプログラムの初期スタックに積む

- 順は、`AT_PHDR`（プログラムヘッダの表が区画に載っている像だけ）・`AT_PHENT`（56）・`AT_PHNUM`・`AT_PAGESZ`（4096）・`AT_ENTRY`（ずらした後）・`AT_UID`・`AT_EUID`・`AT_GID`・`AT_EGID`（どれも0。利用者の区別は、まだ無い）・`AT_SECURE`（0）・`AT_RANDOM`（16バイトを指す）・`AT_EXECFN`（実行したファイルの名前を指す）・`AT_NULL`。
- 積んでいないもの: `AT_HWCAP`・`AT_HWCAP2`・`AT_CLKTCK`・`AT_BASE`・`AT_SYSINFO_EHDR`（vDSOは無い）・`AT_PLATFORM`・`AT_MINSIGSTKSZ`。要る利用者が出たら足す。
- `AT_RANDOM`の16バイトは、CPUが`RDRAND`を持てばその値、持たなければタイムスタンプカウンタを呼ぶたびに進む数と混ぜた値である。**どちらも暗号には使えない**——ほかの出所と混ぜておらず、後から混ぜ直すこともしない。起動ログの`random:`の行がそう言い、`docs/deferred-decisions.md`に決めどきを置いた。
- 位置を決めてリンクした像（自作のプログラム）にも同じものを積む。自作のプログラムは読まないが、形を1つにしておく（`crt0`がそのまま書ける）。

### 4. `PT_GNU_STACK`が実行できるスタックを求める像は断る——Linuxとの差

- このカーネルは、書けるページを実行できないページとして写す（W^X。`ADR-0071`）。スタックは書けるので、実行できない。
- Linuxは、`PT_GNU_STACK`に`PF_X`が立った像（または`PT_GNU_STACK`の無い古い像）を、実行できるスタックで動かす。**ここは合わせない**——W^Xを破ってまで動かす像は、目指す先（musl・Seinas）に無い。断る理由は`-ENOEXEC`で名指しする。
- `PT_GNU_STACK`が無い像は、実行できないスタックで動かす（Linuxの既定とは逆である。musl・GCC・rustcが作る像は、どれも`PT_GNU_STACK`を持つ）。

## Alternatives Considered

1. **像の全体を読む配列を大きくする**（32KiB→数MiB）: 採らない。配列は深さとスロットの数だけ要り、`.bss`が数十MiBになる。範囲を読む口なら、どの大きさの像も同じ道で載る。
2. **配置を1つに揃える**（`ET_EXEC`も`ET_DYN`の配置で載せる）: 今は採らない。既存の37本のプログラムの番地（スタック・ヒープ）が動き、起動ログの参照と、番地を前提にした試験（`nx-stack`）が全部変わる。位置独立の像の配置が落ち着いてから、揃えるかを決める（`docs/deferred-decisions.md`に行を置いた）。
3. **ずらす量を毎回変える（ASLR）**: 採らない。検査は、起動ログの番地が決まっていることに依っている。変える段で、検査の側（番地を揺らがせる記号）と一緒に決める。
4. **補助ベクタを、位置独立の像にだけ積む**: 採らない。形が2つになり、`crt0`が像の種類で分かれる。積む量は約190バイトで、スタックを4ページにした（`ADR-0041`のAddendum）。
5. **`AT_RANDOM`を、固定の値にする**: 採らない。Linuxのlibcは、スタックの見張りの値の種にする。固定だと、見張りが毎回同じになる。弱くても、起動ごとに変わる値を渡す。
6. **実行できるスタックを求める像を、Linuxと同じに動かす**: 採らない（上の決定4）。

## Consequences

- 静的PIEが、ずらした番地で載り、補助ベクタから自分の位置を求められる。実測は、再配置の要らないアセンブリの像（`pie-hello`）で、埋め込みと`spawn`（ファイルシステムを通る道）の両方を通した。muslの像（再配置を自分で行う）は、次の課題（`mmap`・`mprotect`ほか）の後に通す。
- ファイルの上限が16MiBになり、静的な配列が消えて`.bss`が128KiB減った。
- 載せる経路の遠征スタックの使用量は、変えていない（実測。子が走っている間に残る枠へは、何も足していない）。
- 初期データが約190バイト増え、ユーザースタックを4ページにした（`ADR-0041`のAddendum）。
- 補助ベクタの値を自分で確かめるプログラム（`pie-hello`）と、破壊テスト（区画をずらさずに載せる、`AT_ENTRY`と`AT_PHDR`にずらす前の番地を渡す）を足した。
- `AT_RANDOM`は暗号に使えない。鍵や、予測されては困る値をこの16バイトから作る利用者を動かす前に、出所を決め直す。
